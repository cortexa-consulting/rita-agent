# Wrap up

Write down where the work stands, so the next session, or the next person,
starts from the file instead of from scratch.

## Rules

1. **Which memory.** The account (or engagement) this session worked on:
   `projects/<account>/memory.md`, or
   `projects/<account>/<engagement>/memory.md`. If the session touched two
   accounts, update each one's own file. If you can't tell which account,
   ask.
2. **Asking to wrap up is the yes.** Write the update; don't ask again.
3. **Update in place.** Change lines that changed, add new decisions and
   open items under **Where it stands**, **Decided** and **Open**, and keep
   the file under a page. Move what's finished to `memory-archive.md` beside
   it, under today's date (YYYY-MM-DD).
4. **Only what happened.** List files by path, and check each path exists
   before you write it. A decision is something the person decided; a
   suggestion still waiting is "Proposed". If the person says something was
   done and the files don't show it, write it as they said and mark it
   "(not in the files)", in the archive too.
5. **Never in memory:** client figures (sales, units, prices, deal values),
   personal contact details, anything confidential or licensed, anything
   told in confidence, and placeholders like `[COMPANY-01]`. Point to the
   file instead: "Q3 recap drafted, outputs/dalton/drafts/q3-recap.md", not
   the totals, and only to a file you checked holds that number. If the
   person asks you to log one of these, leave it out, say why, and still log
   what's safe ("Q3 has closed; totals not logged here").
6. **Touch nothing else.** Only that `memory.md` and its
   `memory-archive.md`, plus `about-me/memory.md` if the workspace's layout
   changed.

## Reply

Show what you added, changed and moved, as short lists, and say what you
left out and why.
